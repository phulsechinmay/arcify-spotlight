Add a new top-level describe block to the existing `background-data-provider.test.js` file:

**describe('Promise.allSettled partial-failure scenarios')**

These tests call `provider.getSpotlightSuggestions(query, mode)` on a BackgroundDataProvider instance and verify that when individual data sources fail, the others still return results. This tests the inherited BaseDataProvider.getSpotlightSuggestions which uses Promise.allSettled internally.

**Per user decision: test ALL combinations of source success/failure.**

The 6 parallel data sources in getSpotlightSuggestions are:
1. getOpenTabs (calls getOpenTabsData)
2. getBookmarks (calls getBookmarksData)
3. getHistory (calls getHistoryData)
4. getTopSites (calls getTopSitesData)
5. getAutocompleteSuggestions (calls getAutocompleteData)
6. getPinnedTabs (calls getPinnedTabsData)

Test scenarios:
- **tabs fail, others succeed:** Mock tabs.query to reject. Verify results still contain bookmarks, history, etc.
- **history fail, others succeed:** Mock history.search to reject. Verify results still contain tabs, bookmarks.
- **bookmarks fail, others succeed:** Mock BookmarkUtils.getAllBookmarks to reject.
- **all sources fail:** Mock all Chrome APIs to reject. Verify returns empty array (or only autocomplete if that succeeds).
- **only tabs succeed:** All other mocks reject. Verify results contain only tab-sourced results.
- **tabs + history fail:** Both reject, verify bookmarks/top sites/pinned still appear.
- **autocomplete fails, others succeed:** Mock autocompleteProvider to reject.

For each test:
1. Set up Chrome API mocks -- successful ones return realistic data, failed ones `mockRejectedValue(new Error('...'))`
2. Set up BookmarkUtils mocks as needed
3. Call `await provider.getSpotlightSuggestions('test query', 'current-tab')`
4. Verify the result array contains items from successful sources and does NOT contain items from failed sources
5. Verify no unhandled promise rejections or throws

**Important setup for these tests:**
- Pre-set `provider.arcifyProvider` with `hasData: vi.fn().mockReturnValue(false)` to skip enrichment complexity
- Mock `provider.autocompleteProvider.getAutocompleteSuggestions` per test
- Provide realistic mock data that produces actual SearchResult objects through the BaseDataProvider pipeline (tabs with title/url matching query, history items with title/url, etc.)

**A few dedicated tests with small delays** (per user decision: "a few dedicated tests use small delays to validate race conditions and async timing in Promise.allSettled flows"):
- Test that a slow-resolving source (e.g., history with 50ms delay) does not block faster sources
- Test that a slow-rejecting source (50ms delayed rejection) does not block other results

Use `vi.useFakeTimers()` only for the timing-specific tests. Wrap them in their own describe block with timer setup/teardown.

Run the full suite after adding these tests to verify no regressions.
