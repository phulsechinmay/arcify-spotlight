**Step 2: Create `test/unit/autocomplete-provider.test.js`**

Mock Logger using the established `vi.mock('../../logger.js', ...)` hoisted pattern (same as bookmark-utils.test.js). Import `chromeMock` from `../mocks/chrome.js` for consistency (though AutocompleteProvider doesn't use Chrome APIs directly, the setup.js assigns globalThis.chrome).

Mock `fetch` using `vi.stubGlobal('fetch', mockFetch)` in `beforeEach`. Clean up with `vi.unstubAllGlobals()` in `afterEach`.

Mock the following imported dependencies that AutocompleteProvider uses:
- `vi.mock('../../shared/website-name-extractor.js', ...)` -- mock `websiteNameExtractor.extractWebsiteName` to return a canned string
- `vi.mock('../../shared/ui-utilities.js', ...)` -- mock `SpotlightUtils.isURL` to return controlled true/false

Do NOT mock `scoring-constants.js` or `search-types.js` -- let them run with real code (they are pure logic).

Structure tests in these describe blocks:

**describe('AutocompleteProvider')**

  **describe('getAutocompleteSuggestions')**
  - returns empty array for empty/whitespace query
  - returns empty array for query shorter than 2 characters
  - calls fetch with correct Google suggest URL (verify URL format with encodeURIComponent)
  - returns SearchResult array from successful response
  - caches results for 30 seconds (call twice rapidly, verify fetch called once)
  - returns stale cache after TTL expiry (call, advance time 31s with `vi.useFakeTimers`, call again, verify fetch called twice)
  - deduplicates concurrent identical requests (start two calls with same query, verify fetch called once, both resolve with same results)
  - returns empty array on fetch error (mockRejectedValue)
  - returns empty array on HTTP non-ok status (mock { ok: false, status: 429 })
  - returns empty array on AbortError / timeout (mock DOMException with name 'AbortError')
  - logs warning on AbortError, logs error on other errors (verify Logger.warn vs Logger.error calls)
  - limits results to max 5 suggestions (mock response with 8 suggestions, verify 5 returned)

  **describe('fetchAutocompleteSuggestions')**
  - handles unexpected response format (non-array response, missing data[1], data[1] not array)
  - creates SearchResult with correct type (ResultType.AUTOCOMPLETE_SUGGESTION)
  - sets URL to google search URL for non-URL suggestions (when isURL returns false)
  - sets URL to normalized suggestion for URL suggestions (when isURL returns true)
  - calls extractWebsiteName for URL suggestions as title
  - assigns scores from getAutocompleteScore (verify score descends with index)

  **describe('extractWebsiteName')**
  - delegates to websiteNameExtractor.extractWebsiteName
  - falls back to hostname parsing when extractWebsiteName throws
  - strips www. prefix from fallback hostname
  - capitalizes first letter of fallback hostname
  - returns original URL when all parsing fails

  **describe('normalizeURL')**
  - returns URL as-is if it has a protocol (http://, https://, chrome://)
  - prepends https:// to URLs without protocol

  **describe('clearCache / getCacheStats')**
  - clearCache empties both cache and pendingRequests maps
  - getCacheStats returns correct cache size and entries

Use `vi.useFakeTimers()` only within the cache TTL tests (wrap in a dedicated describe with beforeEach/afterEach for timer setup/teardown). All other tests use real timers.

Create `test/unit/message-client.test.js`.

Mock Logger using the established hoisted pattern. Import `chromeMock` from `../mocks/chrome.js`.

**Critical: window global shim.** message-client.js accesses `window.arcifyCurrentTabId` in `handleResult()`. In Node environment (default), `window` is not defined. Set `globalThis.window = { arcifyCurrentTabId: null }` in a `beforeAll` block before importing the module. This avoids switching to jsdom for one property access. Per research, the `|| null` fallback in code handles undefined values, but the `window.` access itself would throw without the shim.

Import SpotlightMessageClient AFTER the window shim and Logger mock.

Structure tests in these describe blocks:

**describe('SpotlightMessageClient')**

  **describe('getSuggestions')**
  - sends message with action 'getSpotlightSuggestions' and trimmed query (per user decision: test action type, not exact payload shape)
  - returns response.results on success
  - returns empty array when response.success is false
  - returns empty array when sendMessage throws (Error('Extension context invalidated'))
  - returns empty array when response is null/undefined

  **describe('getLocalSuggestions')**
  - sends message with action 'getLocalSuggestions'
  - returns response.results on success
  - returns empty array on error

  **describe('getAutocompleteSuggestions')**
  - sends message with action 'getAutocompleteSuggestions'
  - returns response.results on success
  - returns empty array on error

  **describe('handleResult')**
  - sends message with action 'spotlightHandleResult'
  - includes window.arcifyCurrentTabId in message (test with null and with a real tab ID)
  - returns true on success response
  - returns false when response.success is false
  - returns false when sendMessage throws

  **describe('getActiveSpaceColor')**
  - sends message with action 'getActiveSpaceColor'
  - returns { color, groupName } from successful response
  - returns default { color: 'purple', groupName: null } on failure
  - returns default when response has no color

  **describe('notifyOpened / notifyClosed')**
  - notifyOpened sends message with action 'spotlightOpened' (fire-and-forget, no await)
  - notifyClosed sends message with action 'spotlightClosed'
  - notifyOpened does not throw when sendMessage throws (catches error)
  - notifyClosed does not throw when sendMessage throws

  **describe('switchToTab')**
  - sends message with action 'switchToTab' and tabId/windowId
  - returns true on success
  - returns false on error

  **describe('navigateCurrentTab')**
  - sends message with action 'navigateCurrentTab' and url
  - returns true on success
  - returns false on error

  **describe('openNewTab')**
  - sends message with action 'openNewTab' and url
  - returns true on success
  - returns false on error

  **describe('performSearch')**
  - sends message with action 'performSearch' and query/mode
  - returns true on success
  - returns false on error

  **describe('setupGlobalCloseListener')**
  - adds listener to chrome.runtime.onMessage
  - calls onCloseCallback when 'closeSpotlight' message received
  - does not call callback for other message actions
  - returns cleanup function that removes the listener

  **describe('runtime-unavailable scenarios')**
  - handles chrome.runtime being undefined (save/restore pattern)
  - handles chrome.runtime.sendMessage throwing 'Extension context invalidated'
  - For each scenario: verify method returns default fallback ([] for getSuggestions, false for handleResult, etc.)
  - IMPORTANT: Always restore globalThis.chrome.runtime in afterEach or try/finally to prevent test contamination

For the runtime-unavailable tests, save `globalThis.chrome.runtime` before the test, set it to undefined, run the method, then restore. This pattern was specifically identified in the research as necessary for test isolation.

For notifyOpened/notifyClosed fire-and-forget: verify that `chrome.runtime.sendMessage` was called (no await), and verify no throw occurs even if sendMessage throws synchronously.
